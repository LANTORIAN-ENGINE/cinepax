5. DIAGNOSTIC DU BLOCAGE
================================================================================

CAUSE RACINE IDENTIFIEE :
Le canal de vente "CINEP" n'est pas active pour les sessions dans la
grille de programmation VEEZI.

Confirmation par Claire (support VEEZI) :
  "In order to see sessions in Connect the CINEP sales channel needs
   to be selected in programming grid."

Preuve :
  - Les 12 web sessions ont SalesVia: [WWW, POS, MX, RSP]
  - Le canal "CINEP" est ABSENT de cette liste
  - Sans ce canal, l'API Connect (OData.svc/Sessions) retourne un
    tableau vide
  - Sans sessions dans Connect, les endpoints seat-plan et ticketing
    ne trouvent pas les sessions et retournent "session not found"

Schema du probleme :

  Back-office VEEZI ──> Sessions creees avec canaux WWW, POS, MX, RSP
                        |
                        |  Canal CINEP manquant
                        |
                        v
  API V1 (/v1/session) ──> Voit les sessions (filtre par WWW)
                            MAIS pas d'endpoint seat-plan
                        |
                        v
  API Connect (/OData.svc/Sessions) ──> NE VOIT PAS les sessions
                                         (filtre par CINEP)
                                         -> seat-plan inaccessible
                                         -> ticketing inaccessible

7. ENDPOINTS SEAT-PLAN DISPONIBLES (prets a utiliser apres activation)
================================================================================

Une fois le canal CINEP active, trois endpoints sont disponibles :

--- Endpoint 1 : GET seat-plan (plan complet de la salle pour une seance) ---

  GET /RESTData.svc/cinemas/{CinemaId}/sessions/{SessionId}/seat-plan
  Headers : vista-tenant, connectApiToken, VeeziCinemaId

  Retourne :
    {
      "SeatLayoutData": { ... },    <-- plan de salle complet
      "ResponseCode": 0,
      "ErrorDescription": null
    }

--- Endpoint 2 : POST /order/seats/get (sieges dans le contexte d'une cmd) ---

  POST /RESTTicketing.svc/order/seats/get
  Body :
    {
      "UserSessionId": "12345",
      "CinemaId": "0000000309",
      "SessionId": "32217"
    }

  Retourne : SeatData, SeatLayoutData, AreaSummaryData

--- Endpoint 3 : POST /order/seats (affecter des sieges specifiques) ---

  POST /RESTTicketing.svc/order/seats
  Body :
    {
      "UserSessionId": "12345",
      "CinemaId": "0000000309",
      "SessionId": "32217",
      "SelectedSeats": [
        {
          "AreaCategoryCode": "0000000001",
          "AreaNumber": 1,
          "RowIndex": 0,
          "ColumnIndex": 0
        }
      ]
    }

8. STRUCTURE DES DONNEES DE SIEGES
================================================================================

Chaque siege est identifie par 4 proprietes :

  {
    "AreaCategoryCode": "0000000008",   // Zone (orchestre, balcon, VIP...)
    "AreaNumber": 1,                     // Numero de zone
    "RowIndex": 0,                       // Ligne (base 0)
    "ColumnIndex": 0                     // Colonne (base 0)
  }

Parametres de controle dans AddTickets :

  ReturnSeatData: true           -> renvoie les donnees du plan
  ReturnSeatDataFormat: 0        -> 0=tous formats, 1=pipe, 2=structure
  UserSelectedSeatingSupported: true -> active la selection manuelle
  SkipAutoAllocation: true       -> empeche l'attribution automatique
  IncludeAllSeatPriorities: true -> statuts speciaux (House, Broken, Sofa)
  IncludeSeatNumbers: true       -> numeros de siege lisibles
  IncludeCompanionSeats: true    -> sieges accompagnateurs (PMR)

Types de sieges attendus dans les priorities :
  - Standard
  - House (reserves maison)
  - Broken (hors service)
  - Sofa
  - Special
  - Companion (PMR)

9. WORKFLOW DE RESERVATION AVEC SELECTION DE PLACES
================================================================================

Flux complet une fois le canal CINEP active :

  1. GET /v1/websession
     -> Recuperer la liste des seances avec SeatsAvailable, SeatsSold

  2. GET /RESTData.svc/cinemas/0000000309/sessions/{SessionId}/seat-plan
     -> Recuperer le plan complet (grille lignes/colonnes + statuts)
     -> Identifier : disponible, occupe, broken, house, sofa...

  3. Affichage du composant React interactif
     -> L'utilisateur selectionne ses sieges

  4. POST /RESTTicketing.svc/order/tickets
     Body :
       {
         "UserSessionId": "xxxxx",
         "CinemaId": "0000000309",
         "SessionId": "{SessionId}",
         "TicketTypes": [
           { "TicketTypeCode": "0001", "Qty": 2, "PriceInCents": -1 }
         ],
         "SelectedSeats": [
           { "AreaCategoryCode": "...", "AreaNumber": 1,
             "RowIndex": 3, "ColumnIndex": 5 },
           { "AreaCategoryCode": "...", "AreaNumber": 1,
             "RowIndex": 3, "ColumnIndex": 6 }
         ],
         "UserSelectedSeatingSupported": true,
         "ReturnSeatData": true,
         "ReturnSeatDataFormat": 2,
         "ReturnOrder": true,
         "BookingMode": 0
       }

  5. (Optionnel) POST /RESTTicketing.svc/order/seats
     -> Si besoin de changer les sieges apres AddTickets

  6. Paiement via Orange Money / MVola / BNI (externe a VEEZI)

  7. POST /RESTTicketing.svc/order/payment
     -> Finaliser la commande dans VEEZI
     -> Marquer les sieges comme vendus dans le POS
